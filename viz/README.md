# vibe-coding-cn 项目可视化

把整个仓库的结构、机制和设计思路做成一页页可交互的图表，用于**自己快速摸清项目**，
以及**投屏给别人讲解**（尤其是给第一次接触本项目的研一新生讲设计思路）。

零依赖、纯离线：不加载任何 CDN、字体或图表库，断网也能用。图表全部是手写 SVG/DOM。

---

## 怎么用

直接双击 `index.html`，用浏览器打开即可（`file://` 协议下所有功能都正常）。

| 操作 | 效果 |
|:---|:---|
| 点顶栏标签 | 在 9 个页面之间切换 |
| 按 `P` | 进入 / 退出**演示模式**（放大字号、底部出现翻页条） |
| `←` `→` | 演示模式下翻页（也支持 PageUp / PageDown） |
| 按 `Esc` | 退出演示模式 |
| 点右上角主题按钮 | 深色 / 浅色切换（会记住选择） |
| 点分面标签 | 多维度交叉筛选条目 |
| 点目录树 | 展开 / 收起分支 |

## 页面

页面分两层，顶栏用分隔线区分。

### 入门层（1 页）

| 文件 | 内容 | 适合什么时候看 |
|:---|:---|:---|
| `start.html` | 从这里开始：Vibe Coding 是什么 → 这个项目是干嘛的 → 从零开始五步 → 认词 → 选入口 | **第一页**，给完全没接触过的人 |

### 项目层（9 页）

| 文件 | 内容 | 适合什么时候看 |
|:---|:---|:---|
| `index.html` | 总览：规模数字、内容地图、入口导航 | 开场「这是个什么项目」 |
| `design.html` | **8 条设计原则**，每条配仓库真实证据与反例 | 讲设计思路的主场 ⭐ |
| `architecture.html` | 目录树、职责矩阵、内容流向、边界与豁免 | 「东西都在哪、为什么这么放」 |
| `gongfa.html` | 79 条功法登记 × 四阶十二级 × 类型 × 缺口 | 讲身份、来源与评级机制 |
| `faqi.html` | 30 项法器 + 「同一批对象八种数法」对比 | 讲分轴原则最直观的一页 |
| `research.html` | 40 个研究域：对标 / 镜像 / 事实三类 | 讲外部事实与转化管道 |
| `gates.html` | 26 个 Make 目标各守什么不变量 | 讲「门禁即契约」 |
| `roles.html` | 人类 / AI / 机器三套入口对比 | 讲协作机制 |
| `glossary.html` | 修仙词 ↔ 工程概念对照 | 认词用 |

> `start.html` 是入门入口，其中引用了[菜鸟教程《Vibe Coding 入门教程》](https://www.runoob.com/ai-agent/vibe-coding-start.html)
> 的原文段落并标注出处。那篇攻略与本图册是**两条独立的线**：攻略讲通用的 Vibe Coding 入门，
> 本图册展示一个具体项目如何把这件事做成工程体系。两者各自完整，不做逐条对照。

## 文件夹结构

```text
viz/
├── README.md              # 本文件
├── AGENTS.md              # 维护规则
├── start.html             # ★ 从这里开始（入门层入口）
├── index.html             # 总览
├── design.html            # 设计思路（核心页）
├── architecture.html      # 结构与机制
├── gongfa.html            # 功法体系
├── faqi.html              # 法器体系
├── research.html          # 研究域
├── gates.html             # 质量门禁
├── roles.html             # 三种读者
├── glossary.html          # 术语对照
├── assets/
│   ├── README.md          # 资源层说明
│   ├── AGENTS.md          # 资源层维护规则
│   ├── style.css          # 全部样式（含主题令牌与演示模式）
│   ├── app.js             # 共享交互：分面引擎、主题、演示模式、导航
│   ├── charts.js          # 图表组件：环形、堆叠、矩阵、气泡、条形
│   └── data.js            # ⚙️ 生成物：全部页面数据（约 97 KB）
└── build/
    ├── extract.py         # 从仓库提取数据 → assets/data.js
    ├── verify.py          # 静态校验：资源引用、语法、数据字段
    ├── render_check.py    # 真实渲染校验（无头 Chromium）+ 交互测试 + 截图
    └── shots/             # 渲染校验产出的截图（产物，不入库）
```

**`assets/data.js` 是生成物，不要手改。** 它的内容全部来自实时扫描仓库，
页面上每个数字都能在源文件里找到出处。

## 数据更新

仓库内容变化后（新增功法、改了 Makefile、迁移目录……），重新生成数据即可：

```bash
# 1. 重新提取数据（只读仓库，不修改任何仓库内容）
python viz/build/extract.py

# 2. 静态校验（资源引用、JS 语法、数据字段是否都存在）
python viz/build/verify.py

# 3. 真实渲染校验（需要 playwright + chromium，会重新生成截图）
python viz/build/render_check.py
```

只需要第 1 步就能让所有页面显示最新数据；第 2、3 步是给改动过页面代码时用的。

## 数据口径说明

页面上出现的数字都来自实时扫描，几处容易混淆的地方在这里说清楚：

- **「410 行总表 / 79 条登记」**：总表包含历史来源候选，只有 79 条是正式登记的。
  候选没有独立身份、不自动赋级。页面按此区分显示。
- **「0 条正式评级」**：评级规约状态为 `draft`，阈值未校准，所以按设计不产出正式结论——不是遗漏。
- **「外部资源登记行」**：统计的是 `.github/assets/external-resources/*.yml` 里顶层的 `resources:` 条目
  （9 个分类文件，实时扫描）。这个数字与法器数量不是一回事，页面已标注口径。
  `docs/gongfa/faqi-system.md` 正文里提到过「158 条外部资源行」，与当前扫描值不同，
  可能是该文写作时的快照；此处以仓库当前实际内容为准。
- **文件计数**：包含 submodule 指针下的外部仓库文件（如 `tools/external/`），
  所以 `tools/` 的体积远大于其他目录。

## 注意事项

- 本文件夹是**独立附属产物**，不被仓库的任何 `make` 目标或 CI 检查引用。
- 它已纳入版本控制，但只提交必要部分：`build/` 下仅 3 个 `.py` 脚本入库，
  渲染截图（`build/shots/`）作为产物不入库。
- 维护规则见 [AGENTS.md](AGENTS.md)，`assets/` 的规则见 [assets/AGENTS.md](assets/AGENTS.md)。
- 页面只在本地打开，不联网、不上传任何内容。

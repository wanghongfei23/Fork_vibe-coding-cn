Design Principles

这个项目的设计思路

一句话概括：它把文档当成软件系统来治理。有单一数据源、有只读生成视图、有版本身份、 有可执行门禁、有边界契约。下面 8 条原则是这套机制的全部骨架，每条都附仓库里的真实证据。

00八条原则总览点卡片跳到详情

为什么这 8 条值得讲：它们不是"文档规范"，而是可验证的系统约束。每一条都能在仓库里找到一个 脚本、一个 JSON 字段或一次提交来证明它真的在生效——而不是写在纸上。

01–08逐条展开

09这 8 条原则的三种读者效果同一套内容，三种读法

👤 人类读

  • 先看 README.md：定位、入口、徽章
  • 再看 docs/gongfa/README.md：按「当前问题」选方法
  • 需要实例走 getting-started/
  • 从不被要求读 JSON

🤖 AI 读

  • 先读根 AGENTS.md：操作手册与禁止事项
  • 进入目录读该目录的 AGENTS.md：局部边界与验证命令
  • 改完必须跑对应 make check-*
  • 不确定的东西用 TODO 标注，不允许猜

⚙️ 机器读

  • metadata/*.json：登记、等级、来源、SHA
  • taxonomy.yml：路径与角色映射
  • llms.txt / llms-full.txt：AI 索引
  • 生成视图（catalog）禁止手改
证据均可在仓库中按路径核对 → 展开三种读者对比

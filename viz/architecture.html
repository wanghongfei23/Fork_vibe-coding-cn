结构与机制

十棵内容树全部收在 .github/ 下，根目录只留入口文件。 每棵树有唯一职责、明确的「不写什么」，以及一个守着它的检查脚本。

01目录树点目录展开 / 收起 · 括号内为文件数与 Markdown 数

.github/ 内容树

根目录只剩什么

平台入口，不放内容

为什么搬进 .github

「本目录既承载 GitHub 平台配置，也集中存放仓库的知识、工具和自动化内容。 仓库首页仍由根目录 README.md 负责；本目录不放 README.md， 避免覆盖 GitHub 的首页展示。」 .github/AGENTS.md
这是平台约束倒逼结构的典型案例：GitHub 会用根 README 渲染仓库首页， 如果内容目录也放 README，首页展示权就会打架。于是内容整体下沉一层，入口留在顶层。

02职责矩阵每棵树写什么、不写什么、谁在守

读法：「不写什么」这一列比「写什么」更重要——它是防重复的边界。 仓库里每一条重复内容，几乎都来自某个目录越界写了别的目录该写的东西。

03内容流向外部事实 → 可复用方法 → 可执行能力

04边界与豁免什么被排除在检查之外，以及谁在验证这个豁免

被排除出全仓门禁的路径

这些是外部仓库的原始镜像（raw 事实层），保留原样比格式整齐更重要。 但豁免不是无人看守——边界本身有独立门禁。

谁在守边界

05路径约定迁移后最容易踩的三个坑

① 引用要加前缀

从仓库根引用迁入目录，必须写 .github/docs/…。

② 内部链接不加

迁入目录内部的相对链接保持原相对关系，重复加 .github/ 会断链。

③ 平台路径不能动

workflows/、ISSUE_TEMPLATE/、CODEOWNERS 必须留在 GitHub 要求的位置。
目录树与文件数来自实时扫描 → 看门禁体系怎么守着这些边界
